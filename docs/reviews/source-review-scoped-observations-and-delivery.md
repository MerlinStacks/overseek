## Implemented fixes and simplification

1. **Client service labels.** Bounded validated catalog rows replace unchecked arrays. Missing/invalid/duplicate catalogs supply no invented generic options. Own-key lookup prevents inherited object values becoming React labels. Supplied labels take precedence; known static names are explicitly reference-only; unknown code prefixes no longer imply signature, satchel or express coverage. Display labels remain observations, not entitlement or shipment authorization.
2. **Server reference catalog.** Process-wide rows/array are frozen and exported readonly. Each response gets owned copies plus `static-reference` / `not-established` provenance. The reference revision remains **2026-05-22**, not a fabricated deployment-time update. Adapter fallback returns copies rather than the frozen backing array.
3. **Upload publication.** The legacy upload root remains the private invoice/attachment root for recovery. New public assets use `PUBLIC_UPLOADS_DIR` (default `<UPLOADS_DIR>/public`). Explicit blank/relative paths now fail instead of selecting cwd-dependent storage. The broad unauthenticated static mount is removed. Only published avatar naming and hashed normalized email-image naming are served, with bounded files, no-sniff headers and realpath checks rejecting symlink redirects. Narrow read-only fallback supports existing published assets in the legacy root; private invoice/attachment URLs are never served through it. Existing authenticated/signed private resolvers are preserved. No real artifact was moved/deleted/regenerated. Operators must keep storage directories controlled; this is not protection against an operator concurrently replacing root directories.
4. **Visitor observations.** A small shared-Modal view replaces the bespoke overlay, device guessing, URL-only deduplication and unsupported purchase-completion claims. Actor/auth/current-account/visitor-keyed lifetimes, encoded IDs, cancellation/deadlines, byte/row/identity/date decoding and abandonment guards prevent old visitor responses entering a new view. Repeated pageviews remain observable. Source/device/identity/spend bases are explicitly unavailable when missing; zero monetary values survive when currency/basis exists. Reported purchase events do not certify payment/completion. Customer association and spend are labeled reported rather than identity/net-revenue evidence. Oversized/invalid responses fail unavailable, not not-found/empty success. The endpoint still owns account authorization and source coverage; the modal does not certify the entire analytics pipeline.
5. **Advisory leadership.** Each hook owns a unique candidacy, per-effect peer/channel state and cleanup. Disposing one sibling cannot resign another. Messages have bounded shapes/identities/timestamps; freshness uses local monotonic receive time, not sender-controlled future time. Channel changes mask prior leadership immediately; abandoned callbacks cannot publish state; resume clears stale peers. Unsupported/failed BroadcastChannel transport degrades to local advisory leadership. Same-origin peers, suspension and message loss still permit multiple/no leaders: this is load reduction, never exactly-once mutation authority.
6. **Shared work policy.** Queue depth enforcement no longer fetches/removes old waiting/prioritized jobs. Over-capacity is explicit backpressure with existing admitted work intact. Named sync classes get bounded retry/completed-history defaults; unknown and consequential work default to one attempt and retained outcomes. All failed work is retained. Side-effect workers do not automatically replay stalls. These are defaults and an observation-based pressure check, **not an atomic reservation or proof every producer-supplied job option/legacy manual retry is safe**. Existing producers still require their own stable occurrence identities/budgets; explicit deployment/retention planning is required. AI tool capability uses configured exact model IDs, not broad provider prefixes; unknown models are unavailable. Exact allowlisting is not a guarantee of current provider availability.
7. **Order status filters.** A separate decoder reconciles bounded nonnegative integer totals and normalized identities once, rejecting incomplete/malformed snapshots. Scope-keyed cancellable reads mask old counts immediately. Every base/selected/custom filter remains available even at observed zero; missing counts remain unknown. Ordinary named non-submit pressed buttons replace incomplete tab/panel semantics. Loading/error states do not manufacture zero totals or silently change selection. Counts are explicitly local synced observations, not live store coverage.
8. **Shipping settings.** A keyed settings read/draft boundary replaces account-only caches, merged queued hydration and unscoped transient secrets. Reads are bounded/decoded, current settings permission is required, and all provider work is separate from page opening. Missing values are labeled draft defaults; new drafts disable carrier/tracking, opt into no automation triggers and prepare PDF rather than remote printing. Saved unknown enum values must be deliberately selected, not normalized silently. Sender country is explicit. A shared command helper accepts UUID, observed resource/version and bounded data; local save/station-write receipts and audits commit in their transaction. Exact actor/payload replay is checked. Provider test/catalog refresh have pending/complete/uncertain durable gates and no automatic retry. Settings writes cannot pass an uncertain provider gate. Foreign/credential-bearing carrier base URLs and malformed endpoint paths are rejected. Scoped active package/station references are checked. Station token values are returned once, omitted from receipts/replay, dismissed explicitly or after 60 seconds, and reset across account/auth lifetimes. Credentials are cleared after acknowledged save. Dirty drafts are not overwritten by background refresh. Explicit discard does not claim rollback or authorize repeating an uncertain occurrence.
   - API compatibility: flat settings/station mutation bodies are no longer admitted; client and API must deploy together. `GET /settings/auspost-service-catalog` is reference-only; `refresh=true` is retired and `refresh=false` remains false. Provider refresh uses the reviewed POST envelope. `/settings` now requires settings-management permission; workspace public policy reads remain narrow. The new `/settings/stations` response is bounded and explicit about partial coverage. Mapping/trigger editors are bounded explicit JSON arrays, not inferred service matches; richer visual editors can be added without weakening this contract.
9. **Events — partial.** Best-effort emit validates known names/account scope, isolates synchronous/async subscriber failures and never logs full payloads or reports them as successful delivery. Its Boolean remains listener presence. Required subscriptions have explicit identities/disposers; durable occurrence and subscriber receipts distinguish dispatching/complete/uncertain. Incoming IMAP now awaits the required ingestion acknowledgement before marking an upstream message seen; source identity/digest survives regenerated local attachment URLs. Lost acknowledgements remain reconciliation-only, not silently replayed. Missing handlers fail unavailable. The persisted pending/uncertain payload is private DB recovery data, never log output. **Legacy automation and NotificationEngine subscribers still use best-effort delivery. Their source commits are not atomically coupled to this new receipt API. A producer-specific outbox/occurrence migration and delivery-observation semantics remain necessary; do not mark that part fixed.**
10. **Blocked email decisions.** Redis negative-set warming and cache invalidation races are removed from delivery authority. Exact bounded canonical email DB reads decide block state and DB failure propagates rather than authorizing autoreplies. Current inbox read authority and existing mutation authority both gate routes. Stable operation/version/actor/digest receipts make replay explicit; canonical email block and conversation closure commit together after checking contact/conversation versions. Persisted absent-state version tombstones reject old null-version commands after an absent→blocked→absent cycle; retain those version heads as well as occurrence receipts. A cache refresh failure after commit no longer becomes a false mutation failure, and logs omit contact contents. Social/channel IDs are not stored as email addresses: unsupported channel-only blocking returns explicit unavailable. Lists are bounded/cursored; the legacy all-email inbox filter fails closed above its supported window rather than silently dropping blocked contacts. Web inbox/Customers callers now obtain a scoped version observation and validate the mutation acknowledgement, preserving an unconfirmed occurrence instead of blindly repeating. There is no claim of atomicity between an authoritative read and every later independent send: send-time admission remains a separate delivery boundary. Separate native social block identities would require a schema/ingestion policy, not email-field overloading.
