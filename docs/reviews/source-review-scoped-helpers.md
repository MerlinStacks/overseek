# Source review: scoped caches, presets and runtime helpers

## Completed changes

The nine approved actionable files were fixed; `client/src/hooks/useWidgetSocket.ts` was left untouched. Supporting SEO panel integration and regression tests were added. Prior review batches, release work and unrelated plugin/order-panel edits were preserved. No commit, push or live operation was performed.

- **Permissions:** only own-property boolean grants and explicit boolean super-admin status are accepted. Returned maps exclude invalid grants. These are UI checks, not replacements for server authorization.
- **Product search insights:** status and analytics reads/cache keys include owner, account and auth session; both requests consume cancellation signals. No-session, disconnected, invalid-URL and failed states cannot expose old query rows. Runtime validation rejects malformed query records. CTR is recomputed from clicks/impressions; aggregate position is impression-weighted. Zero-impression averages are unavailable, not invented zeroes.
- **Product search panel:** load failures have a retry state instead of a misleading empty state. Sorting uses keyboard-operable non-submit buttons with sort semantics. The connection prompt has a scope-bound serialized/cancellable authorization read and visible errors. Missing query rows no longer claim proof of no impressions or no indexing. Summaries describe returned queries, not guaranteed complete property totals.
- **Saved views:** version-2 browser-local persistence and in-memory stores are scoped to authenticated owner/account, with no signed-out default bucket. Legacy account-only presets are intentionally not restored/migrated because ownership cannot be established. All operations remain local; the silent requests to nonexistent server routes were removed. Stable Zustand snapshots avoid fresh-array subscription loops. Context checks reject cross-context active IDs and edits; obsolete callbacks cannot mutate another scope. JSON-safe bounded filters and persisted records are validated; quota/access failures expose a memory-only warning and do not crash the hook. Views remain plaintext local browser data, not encrypted or server-backed storage.
- **Inventory supplier service:** validates bounded supplier arrays, nonempty identifiers/names and duplicate IDs, and accepts an optional AbortSignal. Invalid successful payloads are rejected rather than installed into product-edit state.
- **Recommendation guards:** accept unknown input safely and validate action discriminants, platforms, identifiers, required fields and finite/nonnegative monetary inputs. Ambiguous keyword/product bid actions are rejected. These helpers do not execute recommendations; server execution must still validate live account ownership, destination, permission, current budget and duplicate protection.
- **Order status:** missing/malformed/prototype-key values become Unknown. Display classes support dark mode and returned metadata cannot mutate the shared configuration. Woo `wc-` prefixes are normalized. The unused guessed advancement rules were removed: store-supported transitions must not be inferred from a badge map.
- **Outbound advisory lint:** normalizes Unicode and whitespace, matches whole words/phrases, and detects complete 13–19 digit card-like candidates without matching fragments of longer digit runs. Candidates are deliberately flagged without requiring a valid Luhn checksum, because mistyped card details are still sensitive. Adjacent digit groups separated only by whitespace/hyphens are treated as one candidate. This heuristic is not comprehensive PII detection or a server-side delivery enforcement boundary.
- **Cross-tab invalidations:** channel construction, setup, posting and close failures are guarded and storage remains a fallback. Both transports validate bounded resource/account/type/timestamp fields; stale/future messages are rejected. New events have IDs and each listener uses a bounded deduplication window. Late callbacks after unsubscribe are ignored. Legacy messages without IDs are accepted only within the same freshness window and deduplicated by validated payload. Messages are untrusted refresh hints, not authenticated mutation commands.
- **SEO scoring:** validates inputs, extracts sanitized text rather than markup/attributes, excludes inline-hidden content, checks nonnegative numeric prices and actual HTTP(S) image URLs, and matches keywords in decoded URL paths rather than hosts/query strings. Keyword spacing is normalized. The analysis panel explicitly labels the score as a heuristic checklist, not a prediction of ranking, traffic or indexing. External stylesheet visibility is not evaluated.

## Next 10: assessment only

Continue after `(1778322462, client/src/utils/seoScoring.ts)` in oldest-last-change order on `origin/main`, omitting already reviewed/modified paths and sorting timestamp ties by path. These files were read and assessed, not edited. The first two share timestamp 1778322462; the remaining eight share 1778447301. The cursor after this assessment is **`(1778447301, server/src/routes/ads/routeHelpers.ts)`**.

1. **`client/src/utils/string.ts` — medium.** `getInitials(null)` enters the object branch and dereferences null; malformed object fields/non-string values can also throw. `charAt(0)` splits non-BMP characters, so some names produce broken initials. `escapeRegex` returns the original runtime value if `.replace` fails despite promising an escaped string. Normalize unknown input, handle null, extract Unicode-safe initials and fail safely for invalid regex inputs.
2. **`server/src/services/analytics/utils.ts` — no change recommended.** This is a two-line re-export barrel, with no independent calculation or authorization logic. Behavior belongs in the referenced implementation modules; do not churn this file merely to change its age.
3. **`client/src/components/Seo/KeywordTrackerPanel.tsx` — high.** Search Console hooks use account-independent keys, and the panel retains selected keyword/form state across account changes. It ignores read errors, while delete/bulk-import callbacks can reject without a visible failure state and suggested-keyword failures are swallowed. Enter bypasses the button's pending guard, allowing overlapping add requests. Keyword/history/recommendation arrays are unchecked. History draws by array index rather than actual dates and assumes ordering, with fixed SVG IDs and no accessible summary. Scope reads/mutations/UI state, serialize actions, show errors, validate/bound imports and history, and make chart/row/tab controls accessible.
4. **`client/src/components/widgets/LiveAnalyticsWidget.tsx` — high.** Existing visitor data remains on account/auth changes and late responses can overwrite a new scope. Polls are uncancelled/unserialized, and a callback dependency on visitor count can immediately restart polling as counts change. Failures become or retain apparently live zero/stale values with no warning. Session data are unchecked, country counts use a prototype-bearing object, and currency formatting defaults to USD without metadata. Add scoped serialized reads, explicit freshness/error states, validation, safe maps and known-currency formatting; describe cart value as observed cart value rather than forecast revenue.
5. **`client/src/components/widgets/SeoKeywordsWidget.tsx` — high.** Its supporting SEO hooks cache status, analytics and movers without owner/account scope and fetch data regardless of connection state. Status errors can look disconnected; analytics failures can look empty. Responses are unchecked, position is averaged equally across queries, and empty data invents zero. A 14-day movers call is labelled 7-day movement, while zero movement is shown as a decline. Scope/gate reads, validate data, expose errors and unavailable baselines, impression-weight position and use accurate period/neutral labels. Connection status is not an authorization boundary despite the source comment.
6. **`client/src/pages/SeoPage.tsx` — high.** The same unscoped status/default-site cache underlies the domain selector. Selection updates locally before an unguarded async default-site mutation; rapid switches can race and failures are hidden. The overview receives the selected site, but the tracker receives no site prop, so the shared selector does not reliably scope its data. Validate sites, bind account/site scope throughout hooks and child panels, serialize/acknowledge default changes, reset scope-local state, show failures and add labelled selector/tab semantics.
7. **`client/src/pages/analytics/AnalyticsOverviewPage.tsx` — high.** Three uncancelled reads update one unkeyed component, retaining prior account/range data and accepting late responses. A single rejection hides all new results while silently preserving old ones. No runtime validation or explicit load/retry state exists. Parent widgets receive date strings derived from browser-local arithmetic converted to UTC, while other sections receive relative day counts; these can disagree around timezones/midnight. Isolate account/auth/range, use cancellable reads and per-section errors, validate responses and use one documented account-timezone range contract.
8. **`client/src/pages/analytics/CLVPage.tsx` — high.** Reads are unscoped/uncancelled and accept late responses; missing auth/account can leave the loader stuck. API data are unchecked and every monetary value assumes `$`. Today, Yesterday, 7d and 30d all map to the same one-month parameter, so the filter labels do not describe the query. The service actually sums a bounded observation window (up to 50,000 orders), not complete customer lifetime revenue. Charts force zero values to a visible minimum bar. Use scoped validated reads, real month/window controls, explicit currency/completeness/methodology, truthful zero bars and accessible chart summaries; do not label partial-window spend as proven lifetime value.
9. **`client/src/pages/invoiceUtils.ts` — no change recommended.** Local designer element IDs prefer UUID and fall back to timestamp/random solely for UI identity, not authorization or invoice numbering. Static toolbox metadata has no live side effects. No actionable defect was established in this file.
10. **`server/src/routes/ads/routeHelpers.ts` — medium.** `parsePositiveInt` accepts partial strings such as `12junk`/`1.5`, unsafe integers and unbounded page values. The action-history caller caps limit but not page/derived skip, so valid-looking input can yield invalid/expensive database offsets. Use strict bounded safe-integer parsing and validate the page/limit product. Replace `any` helper parameters with Fastify types and check accountId shape; membership enforcement remains the auth middleware's responsibility, not an inferred new authorization bypass here.

Eight actionable findings and two no-change recommendations. The next implementation batch should leave the analytics utility barrel and invoice designer metadata helper untouched unless a concrete integration regression requires otherwise.
