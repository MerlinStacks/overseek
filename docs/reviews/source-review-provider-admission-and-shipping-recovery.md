### Maintenance and environment

- Receipt replay/reprocess and account-wide repair/reindex routes are disabled with HTTP 410, not repackaged as a safe repair. Current account/actor and `manage_inventory` are required; status explicitly says disabled instead of returning transient in-process progress. There is no supported automatic repair until reviewed receipt/dependency reconciliation exists.
- Environment parsing is pure and validates required connection shapes, nonblank values, environment names, bounded numeric Redis ports, HTTP(S) search endpoints and production secret length. Validation completes before defaults are installed or success is logged. Supplied Docker/database destinations are never silently rewritten. Errors name variables, not secrets or credential-bearing URLs. Encryption's existing `ENCRYPTION_KEY || JWT_SECRET` fallback remains unchanged; deployed key material is not rotated by this helper. This is configuration validation, not a connectivity test or a full secret-entropy audit.

### Embeddings and AI analysis

- Embeddings always re-read trusted account and account/resource-scoped product snapshots; optional preloaded objects no longer confer authority. Provider input bytes/count/model and exact finite, nonzero indexed vector coverage/dimensions are validated. Oversized text is unsupported, not silently truncated. Batch writes are transactional conditional account/resource/source-version projections; partial failure rejects instead of claiming a complete batch.
- New migration **`20261022120000_embedding_provenance`** adds scalar model/dimension/source-version provenance alongside the existing externally managed vector column. It was written, not applied. Legacy vectors remain provenance-unknown and are excluded. Only `openai/text-embedding-3-small` at 1536 dimensions is supported by this contract; other configured models fail explicitly. Column availability is checked afresh rather than permanently caching a transient result.
- Semantic reads verify complete current local projection coverage and use repeatable-read coverage/query snapshots; unavailable/stale coverage is not represented as a successful empty search. SQL remains parameterized and account-filtered. A capped batch count is not full-account completion. Authorized regeneration/backfill is a separate operator action, never an automatic rollout test.
- Chat and embeddings use separate durable account/hour work budgets and owner-bound leases in existing ScopedOperation storage. Work is charged on admission, including uncertain failures; owner-conditional release changes only the lease, not the charged count. Chat reserves five provider rounds per run; embeddings charge input-vector units; each namespace allows 100 hourly units and one lease. Lease expiry is bounded crash recovery, not proof that a provider did no work. Provider JSON reads retain deadlines through streamed body consumption, cap bytes and reject redirects/non-JSON/unavailable responses without logging bodies.
- Chat requires current actor/account identity and the complete shared read-tool permission set (`view_marketing`, `view_orders`, `view_products`, `view_customers`, `view_cogs`, `view_finance`). Until registry definitions carry per-tool capabilities, this intentionally conservative policy denies partial-domain users instead of exposing other domains. Permissions are rechecked between provider/tool work and before a final answer. The HTTP route passes the actor and returns explicit invalid/unauthorized/limited/unavailable responses.
- Navigation context is only a bounded untrusted user-data hint, not regex-truncated IDs or injected customer/store system instructions. Implicit context database prefetch was removed. Models without supported tools and accounts without their own configured key return unavailable, not invented store facts from a shared fallback key. Tool results, sources, history, iterations and call identities are bounded; repeated call IDs and malformed arguments/messages fail closed. The existing registered-tool validation, account scope and per-tool deadline are preserved. The whole analysis stops waiting at its deadline; an already-running read tool retains its own deadline, but no subsequent provider/tool work is started. Returned prose is labeled model interpretation/general output, not certified profit or forecasts.
- Model catalogs are bounded observed provider responses; failures no longer invent available default models. These changes intentionally alter old unscoped/internal AI callers and require coordinated deployment.

### Digests, stock and Meta delivery

- Digests are now review-only deterministic local observations. Windows are half-open and at most 31 days; only locally synced processing/completed orders are included, capped at 5,000 with an overflow sentinel. Gross recorded totals stay separated by validated source currency. Invalid/missing/overflowed evidence suppresses totals. They are not settlement, refund-adjusted profit or proof of complete provider sync. Ads, previous-period comparisons, new-customer cohorts and savings are explicitly unavailable rather than fabricated zeroes/ROAS money. HTML strings are escaped; no generated model markup or live provider gathering is involved.
- Digest delivery and the scheduler's default-all recipient sweep are disabled. No ad-hoc send bypass remains. Explicit recipient consent, frozen occurrence/recipient identity and durable delivery/reconciliation must be implemented before delivery can be enabled; generated review HTML is not an admission to email it.
- Stock validation uses fresh bypass-cache parent reads or an exact single variation read, not a potentially incomplete all-variation page. Missing/malformed/nonfinite stock is unavailable with null difference. Explicit unmanaged stock is separate and does not pass managed-stock validation. A match is an observation only (`authorizesWrite: false`), never atomic provider compare-and-swap authority.
- Unsupported user/mismatch-override audit/notification paths fail closed until a permissioned write receipt exists; no notification is emitted as if an override were authorized. System stock audits prove local product/account scope, preserve authoritative new quantity and local audit-version basis, keep unknown previous stock null, and propagate missing audit acknowledgement. They do not fabricate a provider version or user attribution. BOM's consumer preserves null old stock and marks non-live validation skipped; a read-before-write comparison is not newly promoted to provider write authority.
- Meta outgoing delivery requires current inbox permission, account/actor/channel/conversation/recipient scope and a stable operation identity bound to the exact payload. ChannelRouter now parses the actual `PLATFORM:page:sender` identity, preserves selected merged-conversation ownership, and forwards the existing chat request identity/actor. Bare social-account-ID sends are no longer accepted. Durable pending/complete/uncertain receipts prevent blind resend; exact completed replay returns the original provider message ID, not another send. Provider acknowledgements must name the expected recipient; failures throw explicit uncertain outcomes rather than indistinguishable null.
- Incoming Meta events are bounded and stored transactionally under a conversation lock with provider-mid/digest receipts and provider timestamps. Ambiguous active page ownership, duplicate legacy conversation identities and changed ownership fail closed. Read/echo events do not create messages; replays neither duplicate nor reopen closed conversations. Profiles are not fetched as a side effect of incoming messages. Attachment links must be bounded credential-free HTTPS values. Stored-message events remain realtime notifications, not a guaranteed durable outbox or proof that a user saw them.
- Constant-time raw webhook signature verification and existing ingress enforcement remain intact. Page listing follows only bounded cursors on the fixed Graph origin, never provider-supplied next URLs; incomplete/failed pagination rejects rather than returning an empty success. Instagram account observations are bounded and distinguish absent linkage from provider failure.

### Shipping monitoring, tracking and fulfillment

- Shipment monitoring is actor/auth/account/order keyed, cancellable and runtime validated. Unavailable reads no longer silently substitute empty/fallback history. Scoped responses declare label/event caps; the UI discloses that only the newest five displayed events are shown. Missing/invalid/future times are not called fresh carrier observations. Carrier links are credential-free HTTPS on approved AusPost carrier domains, and controls are named non-submit buttons with light/dark presentation.
- Refreshes require a stable operation UUID, exact order/label scope and observed label version. Synchronous frontend admission suppresses duplicate clicks; unacknowledged/partial imports retain their identity and block another refresh in that scope. The server records occurrence receipts and per-label gates; pending/uncertain work is not replaced after timeout because tracking import may already have triggered automation. Complete replay returns its recorded result. Successful fresh occurrences have a cooldown; label cancellation/version changes fail admission.
- Tracking scheduler registration is shared/idempotent in-process and only marks registered after queue success. Dispatch requires explicit configured tracking opt-in, uses ordered 25-account pages (maximum four), five-label windows and a dispatch time budget, with sequential durable label occurrence/version admission and structured capped/partial/unavailable outcomes. This is a bounded window, not proof every account/label was polled. Existing pending/uncertain imports require manual reconciliation before new occurrences. Provider tracking responses and normalized event work are byte/count bounded; configured HTTP requests retain their existing deadline. Retrying an old cleanup job is harmless: both scheduled and direct legacy cleanup entry points are disabled, preserving files/references until print/recovery ownership can be reconciled atomically. Storage retention now requires an operator-reviewed replacement workflow and capacity monitoring.
- Fulfillment preserves the existing outer single-attempt gate and adds an inner durable provider-step admission so direct calls cannot bypass it. Only eligible uncancelled labels and eligible same-account orders proceed. A provider update must acknowledge exact order/status/metadata before any local completed status/raw metadata merge. Local merge is transactional and conditional on unchanged order/label versions; stale snapshots cannot overwrite new manual/sync metadata. Shipping lines/items/totals remain untouched. Provider modification time is used only when actually supplied and valid; local now is not substituted.
- Provider order, local merge and order note are separate checkpointed outcomes. A missing/lost note acknowledgement cannot be inferred from label metadata or retried; the acknowledged note ID is retained when available. Unknown currency/cost stays unknown; printed-at is emitted only from an actual recorded print timestamp, including when fulfillment was triggered by label creation. Lost acknowledgements/local conflicts leave uncertain receipts for reconciliation rather than falsely reporting completion. Existing provider order/note helpers remain single requests, without adding retries.
