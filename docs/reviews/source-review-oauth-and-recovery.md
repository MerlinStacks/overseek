# Source review: shared OAuth, recovery and marketing reads

## Completed approved batch

Implemented the eight actionable findings from `docs/reviews/source-review-authorized-and-durable-writes.md`, with supporting integrations. `server/src/services/tracking/BotShieldMetrics.ts` and `client/src/setupTests.ts` remain untouched. Existing checkout changes were preserved; no commits, pushes, migrations, email sends, provider exchanges, help seeding or other live operations were performed.

### Shared OAuth and origins

- The retained `createSignedOauthState` / `verifySignedOauthState` export names now implement opaque database-backed state, not signed account assertions. There is no state-signing secret or development signing-key fallback to exploit. Only a token hash and independent browser-proof hash are stored.
- Strict, bounded state records bind provider, initiating user, account, relative redirect, saved callback URL and optional reconnection target. Creation requires fresh connection permission; reconnection targets must belong to that account and provider. Missing/unavailable durable storage fails closed.
- HttpOnly SameSite=Lax cookies bind callbacks to the initiating browser. Conditional `updateMany` claims make each state single-use across cooperating API processes. Provider mismatch, missing browser proof, expiry, replay and legacy signed states are rejected. Denial callbacks also consume verified state. Permission is rechecked before exchange and again before persistence.
- Google Ads, Meta Ads and Meta Messaging producers and consumers were updated together. Search Console's separate legacy HMAC flow had the same missing durable-claim problem, so it now uses the shared provider/initiator/browser-bound contract too. Completed TikTok protections remain in place and share only the stricter URL builders.
- Public API/app origins are configured, never derived from request Host/proxy headers. Production requires explicit HTTPS origins without credentials, path prefixes, query strings or fragments. Development defaults are localhost-only. Frontend redirects must be relative, bounded and free of scheme-relative/backslash/control-character escapes. Callback path validation permits the existing hyphenated Search Console route.
- Provider/internal messages no longer reach callback error redirects. Raw Meta token exchange requires account scope and marketing-management permission. Existing provider account/page selection behavior remains unchanged; this batch does not introduce a new account-selection interface.

### Advertising observations

- `AdsTools` validates supported platforms and finite nonnegative observations, known currency and valid reporting dates. Account reads explicitly report unavailable observations rather than silently omitting them. Zero-denominator CTR/ROAS remains null.
- Platform aggregates require a compatible currency and reporting window. ROAS is derived from total attributed conversion value (spend × account ROAS) divided by spend, not an equal average of account ratios. Missing-account coverage remains explicit; mixed windows/currencies produce unavailable totals.
- Removed unsupported cross-platform winner/budget recommendations. Provider attribution is explicitly not causal or deduplicated sales revenue.
- Resolved business context is sent identically to optimizer and pipeline. Independent failures preserve the successful component with availability metadata. This wrapper cannot certify completeness inside legacy analyzers; those are assessed below rather than silently rewritten in this batch.

### Password recovery forms

- Recovery submissions have synchronous attempt locks, deadlines, abort cleanup and current-attempt/unmount guards. Inputs are bounded and request acknowledgements validated. Forgot-password confirmation is generic rather than echoing a server string that could disclose account existence.
- Email input is frozen during its attempt. Password reset remounts by URL token, rejects missing/duplicate/malformed links, discards old-token drafts/callbacks and disables resubmission after acknowledged success. Password fields clear on success. Loading, errors and success are accessible states.
- No automatic retries are made after an ambiguous send/reset. Client cancellation does not imply a server rollback. Server token consumption and password policy remain authoritative; these frontend changes do not claim to redesign the backend reset transaction or revoke browser history entries.

### Content and marketing UI

- Content IDs and account scope are bounded, including positive PostgreSQL integer bounds for numeric Woo IDs. The four page/post read/update consumers now resolve internal identity first, then supported numeric Woo identity, instead of an unordered OR that could choose an external-write target nondeterministically. Invalid identifiers produce HTTP 400 before provider calls.
- Ad-copy modal remounts under owner/auth/account/product/open scope. Options and generated-copy shapes are validated; reads/generation have deadlines, cancellation and late-result guards. Generation is synchronously serialized. Native modal-dialog semantics provide Escape handling and browser focus containment; focus is restored on close. Layout is narrow-screen aware with light/dark outer styles. Generated copy remains a dark, explicitly styled display.
- Clipboard success is only shown after a fulfilled write. Failures provide manual-copy guidance; old-scope clipboard completions cannot update new content. No uncleared copied-state timers remain.
- Suggestions remount under owner/auth/account scope, serialize polling and manual refresh, cancel old reads, validate lists/coverage and put current failures ahead of old messages. Fetch time and partial-source notices are explicit. Context controls require `manage_marketing`; advice containing “done” is not shown as a verified completed action.
- Help corrections cover dashboard save acknowledgement/conflict behavior, owner/account/browser-local saved views, heuristic SEO limits, provider reporting/attribution caveats, actual role grants, unsupported theme selectors/cross-device synchronization and absent authenticator enrollment. Revision dates changed only for genuinely edited articles. No help database was seeded and no feature or legal commitment was invented.

## Next 10 — assessment only

Ranked tracked TypeScript/TSX source by latest `origin/main` change after `(1778538599, client/src/data/helpContent.ts)`, excluding modified/reviewed paths and sorting timestamp ties by path. All ten share timestamp `1778538599`. None was edited. Next cursor: **`(1778538599, server/src/services/tools/analyzers/index.ts)`**.

1. **`server/src/routes/ads/copy.ts` — high.** Routes only install generic authentication, then trust `user.accountId` and destructure unchecked bodies. Missing scope can erase Prisma filtering, and there are no explicit feature-generation/manage permissions. Arbitrary `customContext` spreads over authoritative product/store context, enums/strings/numeric bounds are not runtime-validated, and bulk product IDs/work/cost are not reliably bounded by `Math.min(maxProducts || 50, 100)`. Store AOV is invented as 50 and “top products” are actually recently updated. Add trusted request scope, feature permissions, strict bounded schemas, explicit context precedence, generation quotas/deadlines and validated provider/template output. This is backend hardening, not a claim that the newly guarded modal is an authorization boundary.
2. **`server/src/services/tools/AdAlertService.ts` — high.** A campaign's seven-day ROAS is compared with one account-level snapshot from roughly 14–21 days ago, without a campaign identity or compatible window/currency. Threshold options are largely unused; missing provider data/failures become a successful empty alert array. Spend messages assume dollars, and deduplication uses only type/campaign, collapsing collisions across ad accounts/platforms and distinct global anomalies. Repeated critical checks emit events without a durable occurrence/delivery claim. Use like-for-like scoped observations, bounded validated thresholds, explicit partial coverage and stable account/platform/campaign/window identities with replay-safe notification intent. Validate and cap recent-alert limits.
3. **`server/src/services/tools/advisors/MarketingStrategyAdvisor.ts` — high.** Repeat rate is algebraically fabricated from order count rather than measured customer purchases. Account snapshots are treated as channel-level additive money without proving daily grain/currency/coverage; two accounts on the same platform can masquerade as separate channels. Portfolio health averages ratios, missing/error data becomes healthy defaults or zero, and unweighted partial-product margins are used to claim profitable CPA/budget scaling. Seasonal fixed confidence and assumed ROAS become purported revenue estimates; portfolio placeholders are cast as executable campaign actions. Replace with validated measured inputs and unavailable states; keep heuristics explicitly advisory, distinguish periods/spend from actual budgets and omit invented profitability/forecasts.
4. **`server/src/services/tools/advisors/SearchCampaignAdvisor.ts` — high.** Campaign type is guessed from names; unchecked snapshot JSON is summed without grain/currency/completeness proof, campaign ROAS is equally averaged, and 30-day spend is put into actual-budget action fields. Failure or absent sampled Search data is interpreted as not running Search. New-campaign advice invents CPC/CVR/ROAS, confidence, unit prices and revenue lift, plus unverified shipping/category URLs. Site-search samples have no deterministic order/coverage and can divide by zero campaign clicks. Require provider campaign type/account identities, validated compatible observations, actual budgets when actionable, bounded observations and non-executable hypotheses when evidence is missing; remove unverified offer claims.
5. **`server/src/services/tools/analyzers/AnalysisPipeline.ts` — high.** One rejected analyzer or feedback lookup fails the entire `Promise.all` pipeline. Legacy strings gain invented confidence/priority, runtime objects are not validated, dedupe merges identical 100-character prefixes, and actionable recommendations are not deduplicated by account/resource. Metadata reports 11 analyzers run but exposes only five base results and attributes the same aggregate duration to each. User context only boosts matching text, not enforce exclusion constraints. Isolate outcomes, expose per-source status/timing/coverage, validate bounded outputs and preserve calibrated/unknown confidence; keep resource identity and feedback filtering deterministic rather than pretending the pipeline validated executable actions.
6. **`server/src/services/tools/analyzers/BaseAnalyzer.ts` — no change recommended for this batch.** The abstract timing/error wrapper and suggestion constructor have no production subclasses/call sites in the tracked tree (only barrel exports). Its empty-on-error/default-confidence contract would need redesign before adoption, but changing unused infrastructure alone would not fix the active static analyzers. No current production regression established.
7. **`server/src/services/tools/analyzers/KeywordOpportunityAnalyzer.ts` — high.** Unbounded site-search/purchase scans count any same-session purchase regardless of whether it preceded the search, overwrite multiple purchase values, ignore currency/deduplication and attribute the same revenue to multiple terms. Default missing `activeKeywords` becomes an assertion that no paid keyword exists. Nonstring payloads can abort all results, ASCII normalization loses Unicode, and onsite associations are labeled organic conversions. Invented CPC/ROAS/capture-rate/confidence/missed-revenue projections become actionable keyword advice. Use bounded typed chronological observations, explicit attribution/coverage, verified paid-keyword availability and advice-only candidate provenance when evidence is absent.
8. **`server/src/services/tools/analyzers/MultiPeriodAnalyzer.ts` — high.** Array slicing is treated as 7/30/90 calendar days without sorting, deduplicating, checking coverage or validating metric types/currencies. Missing account/platform data is combined as zero and attributed to the first account. Overlapping windows and assumed day counts feed purported significance/trends. Combined spend is represented as a real budget and account IDs are placed in campaign ID fields, so suggested actions target invented resources and can yield negative budgets at small spend. Use account-timezone calendar windows, explicit complete observations and compatible units; separate descriptive comparisons from independent statistical claims and require real campaign budgets/identities for actionable changes.
9. **`server/src/services/tools/analyzers/ProductOpportunityAnalyzer.ts` — high.** Google Shopping product samples and parsed Meta campaign names are treated as complete ad coverage; provider failures become an empty set and false “no ad coverage/no current spend” claims. Capped catalog/orders omit truncation metadata, malformed/string line-item values corrupt quantity totals, missing prices become zero, zero COGS disappears, and averages are not quantity-weighted or currency-validated. All sales are called organic, stock eligibility is ignored, and arbitrary 50% lift/budget/confidence estimates are represented as evidence-based actions. Use typed bounded line items, true coverage states/identifiers, observed-window/currency/quantity-aware metrics and explicitly non-causal candidate advice.
10. **`server/src/services/tools/analyzers/index.ts` — no change recommended.** Static barrel exports introduce no authorization, persistence or data transformation boundary. Preserve exports while hardening concrete analyzers and consumers; no actionable defect established in this file.

Eight actionable findings, two no-change recommendations. Leave BaseAnalyzer and the analyzer barrel untouched unless concrete supporting integration work proves necessary.
