### Shipping operations and print attempts

- The past-labels page is actor/auth/account keyed, uses cancellable validated reads and distinguishes unavailable results from empty samples. It discloses the 100-record cap and unknown coverage instead of presenting a complete ledger. Missing currency is not replaced by AUD and missing settings do not become a claimed auto-completion policy.
- Mutations use a shared synchronous UI lock, explicit confirmation, stable operation UUID and the observed label version. Permissions are checked for each action. Unacknowledged outcomes keep the identity visible and pause other label mutations; successful acknowledgement also requires reviewing current state before another action. Recovery deliberately sends `queuePrint: false`; it does not open a PDF or queue a print through a late callback. Configured backend fulfillment may still follow recovery/printing, and that is disclosed.
- PDF preparation uses the initiating immutable scope, cancellation, MIME/size checks and component-owned object URLs. A prepared download is a separate deliberate link; late completion cannot silently open a window for a different account. URLs are revoked on replacement/unmount. This does not establish PDF content safety in every browser.
- Reprint/recovery/cancellation/manual-fulfillment routes now require operation ID and version. A label-bound advisory lock, conditional version reservation and `ScopedOperation` history/gate prevent overlapping admitted operations. Exact acknowledged replay returns its receipt. Changed identities, stale labels, active queued/picked-up jobs and pending/uncertain gates conflict. Failures preserve ambiguity; another UUID is not a recovery shortcut. This uses the already pending ScopedOperation prerequisite and adds no migration.
- The agent API requires bounded credentials, explicit protocol version and claim-aware request shapes. Protocol **2 or later**, plus any configured minimum, is checked on polling, download and report. Deployment must supply an agent that actually implements these semantics; a version header alone does not prove capability.
- Jobs are conditionally claimed in account/station/job/version scope, with a UUID claim bound to the attempt and label version. Download paths carry that claim; filesystem paths are not returned. Download/report require the same claim and current admitted state. Terminal job/label writes and the report receipt commit together. Same-terminal replay does not run fulfillment again; stale/foreign/uncertain/mismatched reports fail closed. Lost polling/report acknowledgements require reconciliation, not auto-requeue/reprint. Existing attempted jobs cannot be blindly retried/reassigned by the operations helpers.
- Stored print/download bytes require existing path confinement, a non-followed final file descriptor, regular file, matching bounded size and PDF signature. Unsafe/expired/cancelled samples are not dispatched. This does not certify every label-storage race, PDF renderer or external print agent.
- Fulfillment's historical backoff entry point now admits one durable label-bound attempt and never automatically repeats a potentially committed provider call. Missing orders, skipped/failed provider acknowledgement or changed local labels are not marked fulfilled. Pending/uncertain outcomes and post-provider CAS failures remain for reconciliation. Missing fulfillment configuration defaults to keeping the order in dispatch, not silently enabling completion.
- These controls cover the reviewed past-label/agent paths and their necessary retry/fulfillment integrations. They are not a complete review of every shipment creation, tracking, bulk operation, carrier adapter or direct database writer. Physical exactly-once printing cannot be guaranteed by a server claim: the upgraded agent must persist attempt identity and never print twice on response/download retries. No external agent implementation was present in this repository, so coordinated rollout remains mandatory.

### Chat settings and advertising onboarding

- Chat settings use actor/auth/account-bound reads, fully validated nested configuration, bounded strings/colors/Booleans and explicit same-day hours. Enabling business hours requires a valid IANA timezone; overnight intervals are unsupported instead of ambiguously inferred. Invalid legacy configuration is unavailable, not shallow-merged into apparently valid editable defaults. Missing configuration starts disabled. Offline markup is preserved as editable source, not rendered as trusted HTML in this panel.
- Drafts are protected from scope changes and ordinary refresh overwrites; pending writes lock synchronously. Failed/conflicted/ambiguous saves retain the draft and block blind retries. Explicit discard/reload and dirty-unload warnings are provided; browser abort does not imply rollback. This does not add a global SPA navigation blocker.
- The route retains its inbox mutation admission and additionally requires `manage_channels`. Storage validates the entire versioned request, conditionally updates the AccountFeature timestamp with a strictly advanced acknowledgement version and saves an actor/request-bound replay receipt. Changed/stale versions conflict. Storefront sync is only requested after a newly acknowledged save, not on receipt replay; the response/UI explicitly says **requested, unconfirmed**, not “live widget updated.” There is no claim of a durable storefront-sync outbox or successful remote propagation.
- The ads step requires the verified onboarding account and current marketing authority. Reads and connection/OAuth callbacks are bounded, cancellation/scope guarded and synchronously locked. Google initialization accepts only the exact HTTPS Google authorization origin/path, not any scheme-allowed navigation destination. Abandonment clears local credentials and prevents late redirects/parent mutation.
- A dedicated Meta onboarding endpoint atomically saves a bounded credential/identity and operation receipt; collisions with existing accounts require reconciliation instead of replacement/duplication. The response and receipt exclude raw credentials and explicitly say `saved-unverified`. The step does not set `metaConnected: true` merely because a row exists, and never stores the secret back into the parent draft. Other existing ad-account management routes were not globally rewritten or certified. Credential persistence follows the existing ad-account storage mechanism; this batch does not claim a new credential encryption/migration policy.

### Purchase-order and accessible presentation

- Purchase-order list reads are actor/auth/account/filter/page scoped and runtime-validated, with explicit error/retry states and current inventory authority. Source amounts are shown with currency explicitly unknown; malformed/missing values are unavailable. Create navigation requires `manage_inventory`; existing safe tracking-link behavior is retained.
- Conversations have separate named native open/bulk buttons, pressed states, focus preloading and a safe invalid-time label. Malformed label/reason collections no longer break the row or become unchecked color styles. Bulk clicks do not also open the conversation. No admin authorization claim was inferred from sidebar presentation.

### Observed exits and event counts

- Exit/event panels have separate actor/auth/account/window-scoped validated reads, cancellation and unavailable/retry states. A failed read is not “Great news,” an empty observation or a zero conversion rate. The 50-page sample is disclosed, and its observed exits are not asserted to prove causal friction or actual revenue loss.
- Currency coverage is not established by the legacy exit data, so the UI does not display or aggregate money. The existing backend numeric field aliases remain for compatibility and are not promoted into accounting evidence.
- Backend failures propagate instead of returning successful empty arrays. Account/window/exit-threshold inputs are validated. Event counts use event creation time with a half-open end, not the session's latest activity timestamp. Independent pageview/cart/checkout/purchase counts are labeled as events; fabricated funnel conversion/drop-off rates are now null. This does not establish unique-person ordered conversion or complete live tracking coverage.
