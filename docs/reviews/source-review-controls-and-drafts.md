# Source review: frontend controls and PO drafts

## Implemented

- Date-range controls are explicit non-submit buttons with pressed-state labels, wrapping and dark styles.
- Device/browser badges normalize inputs, distinguish unknown devices and expose a combined accessible description. Specific browsers take precedence over generic Chromium/Safari matches.
- Supplier selection keeps a stable combobox input, supports arrow/Enter/Escape navigation, bounds displayed matches, rejects ambiguous records and guards disabled actions. Supplier creation remains keyboard reachable outside the listbox.
- BOM rows distinguish unknown stock from zero, block incomplete previews, calculate bottlenecks from component capacities rather than names, and expose accessible expansion controls. Single sync writes are serialized and mutually exclusive with bulk sync; HTTP success alone is not successful stock-write acknowledgement.
- Inbox loading has one accessible status, a mobile-first layout and dark surfaces.
- Status Center reads use the existing cancellable serialized widget slot under an account/auth key. Invalid, unknown, stale or failed observations cannot present current overall health as healthy. Details use explicit units and never invent a currency; provider error details stay hidden.
- Haptics detect native platforms rather than the mere presence of Capacitor, lazy-load the optional plugin, use native enum values, complete selection lifecycles, bound browser durations and suppress delayed feedback after disable/unmount. Feedback is optional and honors reduced motion and hidden documents.
- PO drafts use a versioned owner/account/PO key and validate dates, statuses, bounded fields, custom or linked lines, finite nonnegative quantities/costs and a mandatory nonfuture 24-hour timestamp. Unowned legacy drafts are not restored or migrated. Storage failures never crash the form. Restoration must happen before writes, and server-read failures leave persistence paused.
- Draft clearing cancels pending writes and prevents the unchanged cleared snapshot being written again. Valid pending edits flush on pagehide. Ordinary unmount/navigation, logout and scope changes deliberately cancel pending debounce writes rather than persisting potentially stale forms. Local recovery is best effort, stored in plaintext on this browser, not a server save or a guaranteed crash-recovery mechanism.
- The PO form remounts under owner/auth/account/resource scope, aborts pending reads and ignores obsolete responses. Save/delete callbacks cannot navigate a different scope. Same-tick duplicate save/delete requests are blocked locally; this does not replace server-side idempotency.

`client/src/components/ui/PageSkeletons.tsx` and `client/src/hooks/useMobile.ts` remain untouched, as approved. Existing unrelated release and plugin changes were preserved. No commit, push, live inventory operation, email, coupon creation or live seeding was performed.

## Next 10: assessment only

Continue from the reviewed batch's oldest-change cursor on `origin/main`, excluding changed paths and reviewed no-change paths, with path sorting for timestamp ties. These ten share last-change timestamp **2026-05-09 10:27:42 UTC**. None was edited in this batch.

1. **`client/src/hooks/usePermissions.ts` — medium.** Permission lookup uses inherited properties and truthiness (`permissions[permission]`, `permissions['*']`), not own-property boolean grants. An absent permission named `constructor` or an invalid string grant can be treated as allowed. Use validated boolean maps and own-property checks; retain server enforcement as the authority. AccountContext currently casts the permission payload rather than validating it.
2. **`client/src/hooks/useProductSearchInsights.ts` — high.** Query keys contain only permalink, not authenticated owner/account, while requests use current account credentials. The shared query wrapper adds no scope. Cached product queries can therefore appear in a different account for the same URL; disabling a query does not hide existing data. Responses are unchecked, errors are omitted, and CTR/position are averaged equally across rows instead of weighting impressions. Add scope-bound cancellable reads, validation, explicit errors and mathematically appropriate aggregates (CTR from total clicks/impressions; position weighted by impressions).
3. **`client/src/hooks/useSavedViews.ts` — high.** Persistent store/cache keys contain account only, so different users of the same browser/account share filters. No-session use writes to `default`; persisted payloads are unvalidated. `getViewsForContext` returns a fresh filtered array from a Zustand selector, which can cause unstable snapshots with the installed store version. Active IDs can reference other contexts. Fire-and-forget requests target saved-view routes absent from current server source and ignore non-2xx responses; rename is local only. Add owner/account scoping, stable selectors, schema validation and either an explicit local-only contract or a real verified sync implementation.
4. **`client/src/hooks/useWidgetSocket.ts` — no change recommended.** Subscriptions remove the exact registered handler, react to socket/connection/enabled changes and use the current callback without unnecessary resubscription. SocketContext already hides sockets immediately when account/auth scope changes and disconnects old connections. Payload validation belongs to each event consumer; this generic hook is not an authorization boundary.
5. **`client/src/services/InventoryService.ts` — medium.** The supplier array type is only a compile-time assertion. A malformed successful response can enter product-edit state and break supplier consumers. Validate supplier records/array at the boundary and accept an optional AbortSignal. The existing product-edit caller guards late scope updates, so this is not an established cross-account display leak.
6. **`client/src/types/ActionableTypes.ts` — medium.** Runtime type guards use `in` without checking for objects, discriminate on loose property presence rather than actionType, and accept missing/invalid identifiers, platform or numeric values. Null API actions throw, and malformed recommendations can be classified as actionable. Add unknown-safe discriminated validation and validate money/IDs at the execution boundary; static TypeScript interfaces are not runtime validation.
7. **`client/src/utils/orderStatus.ts` — medium.** Missing statuses become `pending` rather than unknown, and inherited map keys such as `constructor` bypass the fallback. Non-string inputs throw; the default workflow assumes the optional custom `shipped` status is installed. Normalize unknown input, use own-key lookup, add dark styles and make workflow advancement depend on supported store statuses rather than this display map.
8. **`client/src/utils/outboundSafety.ts` — medium.** The card pattern misses 17–19 digit PANs and can match a shorter fragment of longer digit sequences. Substring matching flags harmless words such as `dumbbell` as hostile and allows whitespace variants of blocked phrases to bypass checks. Normalize text/spacing, match word/phrase boundaries and use bounded complete candidate detection with an explicit validation policy. This browser-side lint is advisory and must not be represented as authoritative sensitive-data protection.
9. **`client/src/utils/productCrossTabEvents.ts` — medium.** BroadcastChannel construction/posting/listener setup are unguarded and can throw in restricted browsers, bypassing the storage fallback or interrupting an otherwise successful save. Channel messages and storage JSON lack schema, age and size validation; the same event arrives twice when both transports work. Guard both transports, validate bounded account/resource events and deduplicate event IDs. Treat these as invalidation hints, never trusted mutation instructions.
10. **`client/src/utils/seoScoring.ts` — medium.** Raw HTML length counts markup as description content; keyword matches can come from tag attributes or a URL host/query rather than visible text/path. Whitespace is not consistently normalized, invalid/non-numeric prices pass, and missing strings/images can throw. Validate input, extract visible text, parse URL paths and price availability, and label the output as a heuristic rather than ranking evidence.

The next implementation batch should leave `useWidgetSocket.ts` untouched unless an integration regression demonstrates a necessary change.
