### Recipe, theme and product selection

- Recipe import is actor/auth/account/workspace scoped and requires marketing management. It explicitly confirms local graph replacement, clones node/edge data, validates bounded unique node identities/edge references, locks synchronous repeat clicks and closes only after acknowledgement. A declined/failed import does not silently close or claim a save/activation. FlowBuilder maps exact old IDs to new IDs rather than substring-matching edge references. Search/category/close controls are named non-submit controls; categories expose pressed state and layout wraps in narrow/dark views. The existing shared Modal retains focus/background handling. “Keep current graph / close” no longer pretends that merely closing starts a new graph. This is draft import, not content/consent/activation readiness validation.
- Theme injection applies validated bounded solid brand tokens only, with computed contrasting primary foreground; it no longer rewrites semantic blue utility classes globally. Auth/account/color changes and invalid/missing appearance release owned tokens. Multiple overlapping layout owners restore the original baseline even when unmounted out of order, without overwriting an independently changed inline property on cleanup. This is not a visual contrast certification of every legacy screen; use of brand tokens by individual screens remains separately reviewable.
- Product search resets request/result lifetime on actor/auth/account/initial-value/disabled changes, debounces cancellable bounded reads and suppresses abandoned query callbacks. Failed/old queries are not selectable empty successes. Runtime schemas require immutable local/product/variant identity, positive Woo IDs and bounded unique rows; camel/snake Woo-ID aliases must agree. Unresolved variable products never become simple parents. Selecting suppresses re-search; editing a committed query clears the parent selection. The combobox/listbox has unique IDs, keyboard/escape handling and a named disabled-aware clear button.
- Search discloses its 20-product/50-row partial window and excludes unsupported/BOM/unresolved types rather than pretending complete coverage. Unknown stock, currency, images and variant/parent monetary data are not inferred: the picker no longer substitutes parent cost or invents dollar amounts, and its selection DTO intentionally leaves monetary/image evidence absent. External consumers must obtain their own explicit cost/unit/currency evidence; this fixes the observed zero-fallback issue by removing unsupported monetary authority, not relabeling missing backend COGS as known zero.

### Shared query/transport and scoped workspace boundary

- Generic query functions receive the cancellation signal. Disabled reads mask cached data; imperative refetch refuses disabled readiness and rejects failed refresh acknowledgement instead of returning retained old data as success. Explicit ready-but-on-demand reads can opt into `manual` without enabling mount polling. FeedHealthPanel's manual caller was coordinated to use readiness, a scoped lifetime, cancellation and handled acknowledgement errors after the first full run exposed that compatibility case. Generic mutations admit synchronously, disable automatic retries, require variables for non-void contracts, await invalidations and suppress callbacks after unmount. These generic helpers cannot infer tenant permission or make an unkeyed legacy caller account-safe. Explicit scoped read/mutation adapters are exported and all approved shipping workspaces now use actor/auth/account-keyed boundaries, validated DTOs and abandonment guards. Remaining legacy callers, including the next-batch settings page, still require their own migration; cache keys are not authorization.
- Shipping transport accepts bounded scoped relative paths, prohibits authority-header override, retains caller cancellation alongside a deadline, rejects redirects, caps streamed JSON/error bodies and rejects non-JSON success instead of casting `{}` to a valid DTO. Error formatting tolerates malformed arrays/nulls, does not reflect arbitrary non-JSON/HTML bodies and exposes bounded structured HTTP/uncertain mutation outcomes. Workspace reads use this bounded transport plus runtime decoding; selected record/account mismatches are unavailable, not defaults.
- Label PDF preparation validates scope, deadline, byte size, MIME and `%PDF-` signature, then offers a deliberate save link rather than opening a post-fetch popup or printing. A dismiss button, pagehide cleanup and bounded expiry revoke its object URL even if an old caller ignores the returned disposer. Signature/type checks are not a claim that all PDF content is benign or that a file was downloaded/printed. Unit conversion preserves absent and zero separately, rejects negatives/nonfinite/scientific/overflow/unsupported precision, and performs exact supported cm→mm / kg→grams conversion instead of silent ceiling/null coercion.

### Versioned catalog and shipping actions

- Packages and item overrides share a scoped, permission-aware local catalog editor. Editable IDs/drafts cannot move into a new account/auth scope. Bounded reads disclose coverage; keyboard edit buttons, narrow scrolling, explicit discard/disable/delete confirmation, dirty-unload guards and disabled pending controls replace mouse-only selection and optimistic late draft clearing. Validation/conflict/unacknowledged outcomes retain drafts and their operation identity; browser abort does not imply rollback. In-panel changes are guarded; this is not a global SPA navigation blocker or persistent cross-reload draft store.
- New catalog writes require actor/account permission, stable operation UUID, immutable resource and observed version (null only on create), with a full bounded data snapshot. A transaction/account lock, conditional row versions, monotonic timestamps, exact replay receipts and audit acknowledgement commit together. Other default packages are conditionally cleared with newer versions. Package defaults/active state, inner/outer dimensions and forced/fallback/packaging/max weights must reconcile. Overrides require exact same-account parent/variation/package ownership, complete-or-absent dimensions and supported customs/unit contracts. Simple-product duplicates are explicitly checked under the account lock; nullable DB uniqueness is not misrepresented as sufficient.
- Legacy unversioned HTTP catalog mutations are retired before their handlers run. Existing internal service helpers are not a public versioned-write bypass; external clients must migrate. This batch adds no migration and relies on the already pending ScopedOperation prerequisite. Arbitrary direct DB writers remain outside the application lock protocol and must not be used to bypass it.
- Operations now reads one bounded local observation response rather than manufacturing account-wide active/stale/issue counts from missing settings or sampled labels. It labels recorded station state/heartbeat and ticked age rather than certifying healthy/online output. Up to 100 jobs, stations and audit headers are disclosed as windows; raw sensitive JSON is not dumped. Failure/empty/partial states are distinct. Retry/reassign require current print permission, explicit confirmation, stable operation identity, observed job version, zero attempts, unexpired uncancelled label and a recent scoped online destination. Existing attempt-aware worker/service claims remain intact; attempted jobs are explicitly reconciliation-only.
- The shell decodes scoped observed fulfillment policy. Missing/failed/unknown configuration never claims print-success completion; an absent explicit setting is labeled with the actual server keep-in-dispatch default and its basis. Policy is distinguished from evidence that Woo sync or physical printing completed; settings navigation requires current settings permission.
- Hub reads are pure local bounded order/draft observations: opening the new workspace does not call the old read path that can prepare/validate drafts. Missing drafts require a separate explicit local prepare action. Only one scoped draft editor is active, using the shared accessible Modal; address/packing/service saves are deliberate, not blur autosaves. Exact separate dimensions/weight and complete address/country are required; no AU, packaging-weight-as-item-weight or malformed segment fallback is invented. Scoped package/service selection is explicit. Acknowledged edits invalidate prior validation/rates; saved-address validation and saved-draft rate requests are separate actions with their own outcomes. Unchecked legacy rate snapshots no longer supply sortable guessed prices/currency or automatic service selection.
- Create-label wording now discloses billable carrier creation, configured physical output and possible fulfillment consequences. It is a deliberate single-order action requiring current create+print permissions and reviewed order/draft/policy/package versions. Reviewed remote-print actions require an explicitly configured same-account recent destination, not an arbitrary first online station. Source dependency versions are checked again when building/locking the frozen request; old label/fulfillment safeguards remain intact. There is no bulk create-and-print or automatic PDF opening on response. Legacy unreviewed draft/carrier/print-retry HTTP paths are retired in favor of this protocol, including matched trailing-slash routes.
- Workspace action receipts and per-resource gates distinguish pending, complete and uncertain outcomes. Exact successful replay returns its original acknowledgement; pending/uncertain work is never replaced automatically after timeout, provider failure, local CAS conflict or lost response. Reviewed draft/validation/rate writes conditionally update the observed version after their work, so late responses cannot overwrite a newer draft. These local checks do not atomically freeze remote carrier/Woo state or every independent internal worker/configuration writer; uncertain outcomes require operator reconciliation, not a new UUID or forced retry.
