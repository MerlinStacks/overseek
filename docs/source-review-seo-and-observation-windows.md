# Source review: SEO controls and observation windows

## Implemented batch

Eight approved actionable source files were fixed, with supporting read/mutation transport, validation, timezone, API metadata and regression-test integrations. **`server/src/services/analytics/utils.ts` and `client/src/pages/invoiceUtils.ts` remain untouched**, as approved. Existing source-review, release, plugin and order-panel work was preserved. No commits, pushes, live inventory operations, OAuth exchanges, provider writes, emails, coupons or live seeds were performed.

### Strings and pagination

- Initials tolerate null, invalid object fields and non-string input. Grapheme segmentation is used where available, with a Unicode code-point fallback. Invalid regex inputs throw rather than returning an unescaped runtime value.
- Ads integer parsing now accepts only complete positive safe-integer strings within explicit limits. Action history rejects malformed requests with HTTP 400 before querying the database: page 1–10,000, limit 1–100, derived offset at most 999,900. Supporting ads date/limit callers now reject invalid inputs with HTTP 400 and bound lookbacks to 365 days rather than accidentally turning parser errors into HTTP 500.

### SEO account/site contract

- Search Console query keys and invalidations are owner/account/auth scoped; requests consume cancellation signals. Disabled queries expose no cached data. Mutations reject concurrent calls in the same slot and obsolete callbacks; only the captured scope is invalidated.
- The reviewed status, query, movers, tracked-keyword, history and recommendation inputs have bounded runtime validation. Query CTR comes from clicks/impressions. History is sorted chronologically and duplicate/invalid dates are rejected.
- Tracker UI state remounts with owner/account/auth/site context. Enter and button actions share a serialized mutation slot. Add/delete/refresh acknowledgement is checked, bulk input is bounded/deduplicated and failed/partial imports retain the draft. Read and mutation failures are explicit rather than silent empty states.
- Rows and controls are keyboard operable with explicit button types and selected states. History uses observation dates, not array index, for x positions. SVG IDs are unique, the chart has an accessible label, and a date/position/click/impression table is available.
- The existing tracking API is **account-wide**, with no per-property ownership field for keywords, groups, history or refresh. The UI now states this instead of pretending that a domain selector filters those operations. The selected site is passed to site-capable overview/recommendation reads. Switching it remounts site-local UI, but does not migrate or reassign tracked records.
- Default-site changes are serialized and committed locally only after the response acknowledges the requested site. Failed changes retain the prior selection and have a visible error. Domain selection is labelled and disabled while pending.
- SEO widget status, queries and movers have separate loading/error states; connection gates analytics reads. Positions are impression-weighted, missing observations are not zero, and neutral movement is labelled unchanged. **Correction to the previous assessment:** the server's 14-day movers request already compares the last 7 days with the preceding 7. That behavior is retained and now labelled explicitly.

### Live and overview analytics

- Live reads use the existing serialized cancellable widget slot under an auth/account key. Invalid payloads, failed reads and stale observations cannot look like a verified live zero. Country counts use a Map; cart totals are grouped by supplied session currency, not an assumed account/default USD currency. Unknown amounts/currency are excluded and disclosed. The live API now selects the session currency field. Counts describe the returned session sample, not unique people, and disclose the 50-row limit.
- Overview uses independent scoped validated reads, so one failed section does not suppress successful sections. Previous-account/range data disappear immediately; obsolete responses are ignored. The page maintains a single account-calendar reporting window expressed as explicit UTC instants for every section, including CRO and geographic drilldowns. DST boundaries are resolved independently. Missing account timezone uses an explicit labelled UTC fallback; invalid/unresolvable zones produce an unavailable window rather than a guess. Calendar windows refresh across midnight.
- Supporting geographic reads and city expansion are also keyed/cancellable with separate errors and safe country query encoding. Currency is never guessed for geographic totals. Funnel zeros no longer require a minimum nonzero visual bar in this overview's count presentation.

### Observed customer spend (legacy CLV endpoint)

- The page is now labelled **Observed Customer Spend**, not a claim of complete customer lifetime value. Day buttons that all queried the same month have been replaced with real month-window controls. The precise UTC observation dates and in-window repeat-order definition are visible.
- The service uses a deterministic bounded order/session sample, detects truncation with an extra row, excludes future records, reports excluded unidentified orders and emits `observation` metadata (basis, dates, currency and coverage). Email identities are trimmed/lowercased; absent attribution is Unknown, not invented Direct. Source attribution uses the earliest returned in-window session, not proven lifetime acquisition.
- The client validates the metadata and rows, scopes reads to account/auth/window, provides retry states, withholds monetary displays without a single known currency, and does not fabricate empty-customer averages or zero-value chart bars. The legacy endpoint/field names remain for compatibility; its statistical interpretation is explicitly bounded-window spend. Monetary aggregates from mixed/unknown currencies must not be interpreted independently of the unavailable-currency metadata.

## Next 10 — assessment only

Ranked after `(1778447301, server/src/routes/ads/routeHelpers.ts)` on `origin/main`, excluding modified and reviewed paths, with path order for timestamp ties. All ten below share timestamp **1778447301**. None was edited in this batch. The next cursor is **`(1778447301, server/src/services/search-console/KeywordRecommendationService.ts)`**.

1. **`server/src/routes/cohorts.ts` — medium.** Retention month parsing accepts partial strings; values outside the service's 1–24 limit become HTTP 500 rather than validation errors. The summary turns an unobserved latest-cohort retention period into zero (`retention[0]?.retentionRate || 0`), despite the service correctly omitting incomplete months. Add strict request bounds and explicit unavailable/maturity metadata; choose a completed comparison period rather than implying observed 30-day retention. Authentication and analytics permission are inherited from the parent router, so no independent authentication bypass was established here.
2. **`server/src/routes/dashboard.ts` — high.** Authentication/account scoping is present, but inbox/ad insight/context/feedback endpoints do not enforce feature-specific read/manage permissions. Context/feedback and widget-layout bodies are not adequately bounded/validated; arbitrary action strings become pending feedback. Layout GET creates defaults via read-then-create, allowing duplicate layouts under concurrent first loads without a visible unique-key contract. Layout saves destructively replace widgets without a version/CAS check, so concurrent saves can overwrite each other. Add resource permissions, bounded schemas, idempotent initialization and versioned writes; validate widget keys/settings/positions before deleting existing layout content.
3. **`server/src/routes/email/routeHelpers.ts` — no change recommended.** This helper delegates account authorization to middleware and returns already-validated schema output or an HTTP 400. Its current callers supply schema `safeParse` results; no independent bypass or reachable successful-parse-without-data defect was established. Better static types would be optional cleanup, not justification to churn this file.
4. **`server/src/routes/inventory/bomManagement.ts` — high.** Reactivation is authenticated and parent-account scoped, but has no explicit product/inventory edit permission gate and blindly sets `isActive` without revalidating the component, mapping, quantity or current deletion state. This can re-enable a known-invalid component that subsequent sync calculations consume. Reads are unbounded and include child details based only on the parent account relationship, which needs care with legacy cross-account references. Require feature permissions and transactional validated reactivation, bound/paginate reads and use a safe reason-count map instead of a prototype-bearing object.
5. **`server/src/routes/oauthRouteHelpers.ts` — no change recommended.** This small account-presence helper is used after authenticated middleware, not as an OAuth callback state verifier. Account shape/ownership enforcement belongs to that middleware and callbacks must validate their own state. No standalone behavioral defect was established; do not confuse this helper with the separate TikTok callback issue.
6. **`server/src/routes/oauthTikTok.ts` — high, priority first.** Authorization state is only base64url-encoded JSON containing accountId/redirect, and the unauthenticated callback decodes and trusts it before attaching credentials. There is no signature, expiry, provider/initiator binding or single-use claim. The redirect accepts state-supplied absolute destinations through `buildFrontendUrl`; provider/internal error text is reflected into redirects. Replace this with bounded, provider/owner/account-bound, expiring, atomically consumed state and allowlisted same-origin redirects; recheck current connection permission and validate exchanged token fields/expiry. The existing shared signed-state helper also has fail-open nonce handling, so reusing it unchanged is not sufficient to claim durable replay protection. No live forged-state or token exchange was attempted.
7. **`server/src/routes/orders/tags.ts` — high.** The version header is checked against an earlier read but is not part of the update predicate. Concurrent tag or sync writes can therefore overwrite each other's tags/full rawData even when both pass the check. Edit-order authorization and bounded tag schemas are absent in this subrouter, and delete double-decodes Fastify's already-decoded path value, breaking literal percent-containing tags and possibly throwing before the try block. Use transactional/account-scoped CAS or row locking, preserve unrelated current rawData, enforce edit permission and schema bounds, decode exactly once, and make committed indexing failures recoverable rather than only logged.
8. **`server/src/routes/roles.ts` — high.** Role updates/deletion/assignment never call the available permission-cache invalidator, so revoked grants can remain effective for the cache TTL. Assignment body/IDs lack a schema; name/permission maps lack sensible length/key bounds. Role lookup and later writes are separate, with generic errors masking conflicts. Add validated bounded role/assignment schemas, account-bound writes and reliable invalidation for every affected user after role mutations. Keep owner/admin/delegated role-management policy explicit rather than silently changing privilege rules. Membership and foreign-account role checks are already present.
9. **`server/src/services/ai_tools.ts` — medium.** Tool definitions are not enforced at runtime: argument objects, strings, periods/enums and integer limits are cast through to handlers, and `normalizePositiveInt` accepts partial strings/fractional numbers without an upper bound. Registry lookup accepts inherited names instead of own registered handlers. The broker logs complete arguments, potentially including customer search data. Add own-key dispatch, strict bounded per-tool schemas, a nonblank trusted account scope, controlled/redacted logging and bounded execution. This file is not proof that model-supplied account IDs can override tenant context; the registry currently passes the caller's accountId separately.
10. **`server/src/services/search-console/KeywordRecommendationService.ts` — high.** Missing terms from a capped top-1,000 query sample are described as products with no organic visibility, which is not established by sampled/anonymized GSC data. Catalog gap scans are unbounded; raw category arrays and prices are unchecked and price-based priority ignores currency. AI calls lack a timeout, response-status/size validation and full output schema; generation failures collapse into an unexplained successful empty array. JSON repair can turn truncated model output into apparently complete advice. Bound/validate inputs and provider work, expose coverage/provenance/unavailable states, describe gaps as candidate opportunities, disclose CTR-upside assumptions and reject incomplete or malformed model output rather than inventing complete recommendations.

Eight actionable findings, two no-change recommendations. Leave the two helper files untouched in the next implementation batch unless a concrete supporting integration requires otherwise.
