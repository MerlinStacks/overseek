It does not certify WordPress installation or live release publication. Keep the client pin and source-verified installer package in step on future releases. Invalid configuration is unavailable rather than copied as a plausible endpoint. TrackingScriptHelper also stops exposing configuration when this base is invalid.

Authorization callers now use a dedicated exact Google/Meta/TikTok origin/path allowlist instead of the generic HTTP(S) navigator. Backend OAuth state/cookie/signature checks remain the authority; allowlisting a frontend destination is not a substitute. - Popup preparation returns failure when no window is obtained; an inert same-origin window has its opener severed before external navigation. No browser popup behavior was certified by the mocked tests.
- StatusCenterPanel is actor/auth/account keyed, has validated bounded reported-state/detail contracts and single-slot polling/refresh. Unknown/missing/failed/stale/future observations cannot become an “all systems operational” headline. Monetary fields require explicit currency instead of `$` inferred from arbitrary key names. Navigation labels accurately say review settings, not that a sync/webhook test was executed. The underlying status API's broader provider/metric accounting remains independently reviewable.

### Inventory alert settings and content editor

- Alert settings use actor/auth/account-scoped validated snapshots and explicit unavailable states; legitimate zero thresholds survive. Full strict nested save contracts require actual Booleans, integer thresholds 0–3650 and up to 25 unique valid recipient addresses. Enabling alerts requires recipients. The form describes threshold policy, not guaranteed days remaining or proof of future delivery.
- Drafts survive validation/conflict/unacknowledged saves. Synchronous locks, cancellation, late-result guards, explicit discard/reload and dirty-unload warnings replace optimistic default/success behavior. Server reads require `view_inventory`; writes require `manage_inventory`. An account lock, conditional timestamp/version update and actor/payload-bound receipt admit one acknowledged save and exact replay. No test alert is sent by saving settings. This does not add a global SPA navigation blocker.
- Content lists/details/editors are actor/auth/account/kind/resource/page scoped, runtime validated and cancel stale reads. Failed details do not leave a previous selection editable. The list exposes bounded pagination/coverage; current editor scores are explicitly heuristic checks, not ranking evidence. In-panel create/edit navigation and unload guard local dirty/pending/uncertain work. Initial supported tab/local UUID deep links are recognized; this is not a general router-level dirty-navigation blocker.
- The HTML preview is a deliberately toggled formatting-only sandbox. Sanitization removes active tags, all source attributes, links/media and author CSS; CSP denies network/base/form authority. No script, popup escape or top-navigation sandbox flags are enabled. This does not claim that the HTML later deliberately published to WordPress is universally safe for every storefront renderer.
- Reads retain trusted account resolution and `view_products`. Creation/edit/publication additionally requires the new **`manage_content`** permission, exposed in Role Manager. Writes require an immutable local resource UUID for updates, strict bounded fields, current local version and stable operation UUID. Old unversioned callers are intentionally incompatible and must be retired/updated.
- Content admission records an actor/request digest plus a resource-bound update gate or actor/kind-bound create gate. Conditional local version reservation precedes one provider attempt. Successful local acknowledgement and receipt/gate completion commit together; exact replay does not call WordPress twice. Pending/uncertain operations block replacement identities until reconciled. A provider timeout, invalid response, local conflict or lost acknowledgement is not blindly retried.
- WordPress page/post create/update helpers now disable automatic request backoff for these writes. Other existing WordPress API operations keep their prior retry policy; this batch does not globally certify that policy. Remote changes outside OverSeek are **not** atomically version-locked by local CAS; compare actual WordPress revision/content before reconciling conflicts. Do not reset gates or create replacement documents to hide uncertain provider outcomes.
- Undated WordPress drafts remain explicitly undated in the content DTO. Legacy required DB date columns may hold the local observation timestamp, accompanied by raw observation metadata; presentation masks absent provider creation/modification dates as null rather than claiming those internal fallback values are provider dates. Receipts return the same safe presentation, without raw provider payload. Existing legacy records retain their documented synced-date basis.

### BOM costs, picklists, freshness and deployment recovery

- BOM cost calculation now returns an explicit complete/unavailable result with nullable total/currency. It validates bounded component sets, exclusive source ownership, finite nonnegative cost, positive bounded quantity and waste ratio 0–1. A common source currency and explicit per-component-unit basis are required; missing variant cost does not fall through to a different source and unknown components are not free. Nested BOM resolution/conversion is not invented. No tracked caller of this exported helper was found; external consumers must adapt to its result contract.
- Picklist preparation requires a bounded account/status/window snapshot, unique product identities, whole-unit positive quantities, reconciled per-order totals and escaped text. Backorder/unknown are distinct from out-of-stock. Fractional/unit-ambiguous demand is explicitly unsupported, not silently rounded or printed as zero. The authorized parent captures actor/account/status/100-order cap, cancels old work, suppresses late scope callbacks and closes superseded/unmounted previews. A prepared preview contains a separate deliberate print button; there is no automatic `window.onload` print. No stock is reserved/consumed and no physical print was tested.
- Timestamp utilities distinguish never, invalid/unknown, future and observed age; timezone-bearing ISO calendar validation and an injectable clock replace permissive Date parsing. Only one minute of future skew is tolerated as current. SyncStatus now has explicit unknown/future presentation instead of missing color/label cases. Formatting a timestamp alone does not establish source availability.
- Deployment recovery no longer deletes any cache, waits on `serviceWorker.ready`, writes storage or automatically reloads (including dev disconnects). An in-memory cooldown/idempotent handler installation offers an explicitly confirmed reload only after the user reviews drafts/in-flight work. Cleanup removes listeners/prompt; original error reporting is not suppressed. Raw URLs/errors are no longer sent as recovery telemetry. This intentionally favors safe manual recovery over an unproven automatic deployment diagnosis; other error-boundary/global-navigation behavior remains separately reviewable.
