### Pagination and modal drafts

- Pagination keeps a local destination draft and commits on Enter/blur, not on each digit. A synchronous admission ref suppresses repeated acknowledgement of the same destination before new props arrive. Pages/totals must be safe bounded integers; empty/invalid pagination is explicitly unavailable/no-pages instead of a synthetic page one or NaN navigation. Per-instance IDs, explicit button types, labels, wrapping layout and dark styling replace shared IDs and accidental form submission. Existing button titles and numeric input semantics are retained for consuming screens.
- `useModalDraftState` requires an explicit scope key. Scope/open transitions reset synchronously before exposing the next render, clone initial data and no longer schedule an unguarded microtask. In-scope initial-prop refreshes preserve edits; reset uses the latest caller initial value. Drafts are not written to unscoped persistent storage. Callers must still guard asynchronous request callbacks; this hook is not delivery authorization, an in-flight lock or a global navigation blocker.

### Tag mappings, extraction and sync

- Stored and submitted mappings are strictly validated and bounded: actual Boolean enabled flags, bounded product/output tag names, mapping/tag counts and hex colors. Legacy single product-tag fields are supported through normalization, without coercing objects or `"false"` into active rules. Empty/null configuration is a known empty mapping set; malformed configuration or missing account is an error.
- One input product tag can map to multiple output tags with case-insensitive union semantics instead of last-write-wins loss. Output unions retain manual tags and reject malformed/oversized values. Order batches, line items and unique product lookups have explicit limits; missing products, malformed tag metadata and incomplete product coverage fail instead of producing apparently complete no-match arrays.
- Product-tag suggestions use deterministic bounded reads (5,001 sentinel rows) and disclose whether the 5,000-product sample is complete. They are not advertised as a complete catalog. Unsupported/oversized tag data fails visibly. A failed suggestion read does not hide or clear stored mappings.
- Account routes require selected account/membership and current permissions. Mapping reads allow order-view or mapping-management access; catalog suggestions and writes require **`manage_order_tag_mappings`**, exposed in Role Manager. Saves validate the full request and use an account `updatedAt` compare-and-set with a strictly advanced acknowledgement version. Unrelated account-setting edits can intentionally cause a conflict; no independent mapping version is invented.
- The settings UI is keyed by actor/auth/account, validates snapshots/catalog coverage, cancels old reads and uses stable local row IDs. Product tags use one-per-line input so comma-containing names survive a round trip. Native labeled fields, partial/error states, dirty unload/discard prompts, synchronous write locks and current-attempt guards replace implicit success and stale callbacks. Conflicted/unacknowledged writes retain local edits and pause further mutations until explicit discard/reload. Saving configuration does **not** initiate a sync.
- Audited extraction consumers: order-detail and explicit reindex reads fail closed on incomplete extraction; sync no longer retries an incomplete batch into empty fallback tags. An unavailable extraction skips the page's bulk search indexing and leaves existing indexed tags alone rather than claiming a new complete projection. Existing sync semantics still persist valid orders and emit their lifecycle events; no job was executed here.
- Sync locks existing order rows before reading/upserting their raw data, preserving local manual tags through provider updates. Indexing paths union manual and computed tags rather than overwriting manual tags with computed-only arrays. New regressions exercise row locking/manual-tag preservation and skipped indexing after extraction failure. This does not certify a live index as current: existing asynchronous index/outbox races, worker recovery and projection lag require real staging checks. Do not clear outbox intents or run a wholesale re-sync as a test/recovery shortcut.

### Supplier creation

- The creation modal is keyed by actor/auth/account/open lifecycle, requires current `manage_inventory`, keeps a stable UUID for one creation, validates ordered whole-day lead times and requires a deliberate currency selection. It has native labels, bounded fields, dark/narrow layouts, cancellation, synchronous locking and guarded late callbacks. An ambiguous result shows the creation identity and blocks blind retries/new identities until the operator reconciles the supplier list. Existing drafts are not carried into another account.
- The creation endpoint requires authenticated selected account and current inventory authority. Strict runtime fields, stable UUID, explicit uppercase currency, optional bounded contact details and lead times from 0–3,650 replace permissive parsing/default USD. Min/max order is validated. Duplicate/foreign primary identities conflict rather than exposing another account's supplier.
- Creation and an account-bound request-digest receipt commit in one transaction under a stable operation lock. Same-identity/same-payload replay acknowledges the receipt without creating twice; a changed payload under the same identity conflicts. This uses the prior `ScopedOperation` table; it adds no new migration. Receipts record creation acknowledgement, not a promise the supplier was never subsequently changed/deleted.
- `SuppliersList` now uses the same admitted creation modal instead of an older incompatible/unversioned inline create form; its mounted state is actor/auth/account keyed. This batch does not claim a full review of that screen's unrelated edit/delete/item-write workflows or change their existing backend contracts.

### Metadata and composer

- Order metadata has bounded runtime shape validation, explicit unsupported/oversized state and React-escaped plain text. Product options/custom fields/uploads have mutually exclusive ownership using exact option keys rather than incidental substring matches. Line breaks, display labels and valid Unicode/mojibake handling remain supported.
- Image extraction parses actual HTTPS URLs and raster pathname extensions; query-string extension lookalikes, credentials, malformed/oversized URLs and arbitrary SVG/data schemes do not become automatic images. Up to 12 images per field are offered. **External images do not load until the user explicitly requests them**; controls disclose the host, use no-referrer and native keyboard buttons, and reset error/load state by URL. The host still sees the network request after consent; no anonymity guarantee is made. This is not a claim that previously escaped text executed HTML.
- The canned-response toolbar now opens a chooser without replacing the existing rich-text draft with `/`. Toolbar-opened reply selection preserves/appends to that draft, including drafts that begin with a slash; intentional typed-shortcut selection retains its existing shortcut replacement behavior. Opening management no longer clears the input. The local chooser can be closed with Escape.
- Composer readiness uses shared inert HTML parsing/entity decoding in toolbar, keyboard submission and send/schedule hooks. Encoded nonbreaking/zero-width whitespace does not count as meaningful text. Attachment/image-only messages deliberately require accompanying text; the UI does not advertise support the send hook lacks. Upload/AI-generation/pending/sending state gates send/schedule/approval controls consistently, with actual send/schedule buttons declared non-submit and signature pressed state labeled. SMS length uses the same decoded text for its existing display calculation; no new provider-calibrated segmentation claim is made.
- These are composition safeguards, not a replacement for parent/server delivery authorization, request identity, provider idempotency, content sanitization or broader inbox scope/recovery controls. No actual send or schedule was created.
